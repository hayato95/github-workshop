# git/GitHub かんたんチートシート（未経験者向け）

## そもそも「ブランチ」とは？

プロジェクトの作業履歴には、常に「main（本流）」という1本の線があります。
ブランチとは、そこから分かれる「作業専用の枝」です。

- mainは常に「動く状態」に保っておきたい
- でも自分の作業中のコードは、書きかけでエラーだらけの時間帯もある
- なので、mainとは別の枝（ブランチ）を作って、そこで安全に作業する
- 作業が終わって「ちゃんと動く」と確認できたら、mainに合流(マージ)する

## なぜブランチを分けるのか？

- **他の人の作業を壊さないため**: 4人が同時にmainを直接書き換えると、お互いの変更で衝突・事故が起きやすい
- **レビューをしてから取り込むため**: ブランチ単位でPull Request(PR)を作ることで、「このコードで本当に良いか」を他の人がチェックできる
- **やり直しがしやすいため**: 作業用ブランチで失敗しても、mainには影響しない。ブランチを消せばなかったことにできる

## 今回のワークフロー全体像

```
1. issueを確認する（自分が何を実装するか）
2. mainから自分の作業ブランチを作る
3. 作業ブランチでコードを実装する
4. 変更をcommitする
5. 作業ブランチをGitHubにpushする
6. Pull Request(PR)を作る
7. 他のメンバーにレビューしてもらう / 自分も他の人のPRをレビューする
8. 問題なければmainにマージする
9. GitHub Actionsが自動でテストを実行し、結果を確認する
```

## コマンド一覧

### 最初に1回だけ（リポジトリを手元にコピーする）
```bash
git clone <リポジトリのURL>
cd <リポジトリ名>
```

### 2. 作業ブランチを作る
```bash
# mainを最新の状態にしてから
git checkout main
git pull

# 新しいブランチを作って、そのブランチに切り替える
git checkout -b feature/issue-2-fortune
```
- ブランチ名は「何をするか」がわかる名前にする（例: `feature/issue-番号-内容`）

### 3〜4. 変更を保存する(commit)
```bash
# 変更したファイルの一覧を確認
git status

# 変更をステージに追加する
git add app-logic.js

# コミット（変更内容に短いメッセージをつけて記録する）
git commit -m "feat: 運勢判定機能を実装"
```

### 5. GitHubにアップロードする(push)
```bash
git push -u origin feature/issue-2-fortune
```

### 6. Pull Request(PR)を作る
- GitHubのリポジトリページを開くと「Compare & pull request」ボタンが出てくるので押す
- タイトルと説明を書いて「Create pull request」

### 7. レビューする/される
- 自分がPRを出したら、他のメンバーに見てもらう
- 他の人のPRが来たら、「Files changed」タブでコードを見て、コメントを残す
- 問題なければ「Approve」する

### 8. マージする
- レビューでOKが出たら、PR画面の「Merge pull request」を押す
- マージが終わったブランチは削除してOK（GitHubの画面にボタンがある）

### 9. GitHub Actionsを確認する
- push または PR作成のタイミングで、自動テストが走る
- PR画面や「Actions」タブで ✅(成功) / ❌(失敗) を確認できる
- ❌ の場合はログを見て、テストが落ちている理由を確認し、修正してpushし直す

### あわせて使うコマンド
```bash
# 今の状態を確認する
git status

# 変更内容を確認する
git diff

# ブランチの一覧を見る
git branch

# mainの最新を自分のブランチに取り込みたいとき
git checkout main
git pull
git checkout feature/issue-2-fortune
git merge main
```

## 困ったときは
- 何が起きているかわからなくなったら、まず `git status` を実行して今の状態を確認する
- 不安なときは焦らずAIに聞いてみてもOK（今どういう状態か、`git status`の結果を貼って質問すると答えやすいです）
