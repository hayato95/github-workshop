対象: プログラミング未経験者4人 + 主催者1人
所要時間: 約4時間
目的: アプリの完成度ではなく、issue作成〜ブランチ〜実装〜PR〜レビュー〜マージ〜CIという
開発の一連の流れを体感してもらうこと。

## 事前準備（当日より前）
- [ ] このリポジトリをGitHub上に作成し、push しておく
- [ ] 4人をコラボレーターとして招待しておく（Settings > Collaborators）
- [ ] 親issue（`docs/issues.md`のたたき台参照）を作成しておく
- [ ] 親issueの内容をもとに、sub-issueを4件作成しておく（`docs/issues.md`の下書きを利用）
- [ ] 各参加者にリポジトリのURLとissue番号を割り振っておく
- [ ] 参加者のPCに `git` がインストールされていることを確認（`git --version`）

## マージ順のすすめ方
4人とも同じ `app-logic.js` を編集するため、マージの順番次第では軽微なコンフリクトが起きることがあります。
- 基本方針: PRが早く準備できた人から順にマージしてOK（4関数はファイル内で離れた場所にあるため、通常は自動でマージされます）
- コンフリクトが発生した場合: 慌てず「学びのチャンス」として一緒に解消する（`docs/git-cheatsheet.md`の`git merge main`の手順を参照）
- 担当D（`getLuckyMessage`）は担当A（`getFortune`）の返り値の文字列に依存しているため、可能なら担当Aを先にマージすると混乱が少ない

## 進行のコツ
- 実装そのものよりも「git/GitHubの操作を1人でひと通り経験できたか」を優先する
- 詰まっている参加者がいたら、`git status` の出力を見せてもらいながら一緒に状況を確認する
- レビューは「間違い探し」ではなく「一緒に確認する」という空気づくりを意識する
- 時間が押した場合は、レビュー時間を短縮してでもマージ〜CI確認〜動作確認までは必ず到達する
