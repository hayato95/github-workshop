# issue 下書き

このファイルは、ハッカソン当日に使うissue本文の下書きです。
親issueは主催者がGitHub上で作成し、その内容をもとに以下のsub-issue 4件を
`gh issue create` で起票します（親issueの文面が固まったら、内容をすり合わせてから起票してください）。

---

## 親issue（例・主催者が作成する想定のたたき台）

**タイトル**: おみくじアプリを完成させよう

**本文**:
```
今日のおみくじアプリを完成させます。
`app-logic.js` の中にある4つの関数はまだ中身が実装されていません（TODOのまま）。
それぞれ担当を分けて実装し、Pull Requestでレビューし合ってmainブランチにマージしていきましょう。

## サブタスク
- [ ] #(担当A: 運勢判定)
- [ ] #(担当B: ラッキーカラー)
- [ ] #(担当C: ラッキーアイテム)
- [ ] #(担当D: 応援メッセージ)

## 完成条件
- 4つの関数がすべて実装されている
- GitHub Actions のテストがすべて緑になっている
- ブラウザで `index.html` を開き、「おみくじを引く」ボタンを押すと結果が表示される
```

## sub-issue 1: 担当A: 運勢を判定する関数を実装する

**ラベル案**: `good first issue`
**ブランチ名の例**: `feature/issue-2-fortune`

**本文**:
```
## やること
`app-logic.js` の `getFortune(index)` 関数を実装してください。

## 仕様
`index` (0〜4の整数) を受け取り、対応する運勢のラベル(文字列)を返します。

| index | 返す値 |
|-------|--------|
| 0     | "大吉" |
| 1     | "中吉" |
| 2     | "吉"   |
| 3     | "小吉" |
| 4     | "凶"   |

例: `getFortune(0)` は `"大吉"` を返す

## ヒント
- 配列を1つ用意して、`index`番目の要素を返すだけでOKです
- 実装例は `app-logic.js` にある `getLuckyNumber` 関数を見本にしてください（同じ考え方です）

## 受け入れ条件
- [ ] `getFortune` を実装した
- [ ] `node --test tests/*.test.js` を実行し、`getFortune`のテストが通る
- [ ] 他の担当者の関数(未実装のまま)には手を入れていない
```

| fortune | 返す値                       |

受け取ります。担当Aの実装内容(文字列の表記)と揃っているか確認しましょう。
