# issue 下書き（参加者向けの参考資料）

親issueは主催者がGitHub上で作成済みです（[#1](https://github.com/hayato95/github-workshop/issues/1)）。

**sub-issueは、当日ワークショップの中で参加者自身が作成します。** これはワークショップで
体験してほしいことの1つ（課題をsub-issueに切り分ける）だからです。

このファイルは、参加者がsub-issueを作成するときに「何を書けばいいか」の参考になる
仕様（関数のシグネチャ・入出力例・受け入れ条件）をまとめた下書きです。当日、担当者は
このファイルの該当箇所を読みながら、自分のsub-issue本文を書いてください（コピペしても、
自分の言葉で書き直してもOKです）。

**注意**: 各関数が返す値の中身（ラベルや色の名前など）は、あえてこの資料には書いていません。
自分で考えて実装してください。テストは「値の中身」ではなく「値の形」（重複していないか、
毎回同じ結果になるか）をチェックする作りになっています。

---

## 今、このアプリはどこまでできてる？

sub-issueを書く前に、まず今のプロジェクトが「何ができていて、何ができていないか」を
ざっくり知っておくと書きやすくなります。中身はこんな感じです。

- `index.html` … 画面そのもの（ボタンや結果を表示する場所）。これはもうできている
- `style.css` … 画面の見た目（色や配置）。これもできている
- `script.js` … 「おみくじを引く」ボタンが押されたときの動き。これもできている。
  ボタンが押されると `app-logic.js` の関数を呼び出して、返ってきた値を画面に表示する係
- `app-logic.js` … 運勢・ラッキーカラー・ラッキーアイテム・応援メッセージを
  「決める」ところ。ここが今回みんなで実装する部分

`app-logic.js` の中には `getLuckyNumber` という関数だけ、すでに実装済みで見本として
置いてあります。「番号(0〜4)を渡すと、対応するラッキーナンバーを返す」だけのシンプルな
関数なので、まずこれを読んでみると他の4関数の実装イメージがつかみやすいです。

残り4つの関数（`getFortune` / `getLuckyColor` / `getLuckyItem` / `getLuckyMessage`）は
まだ中身が空っぽ（`throw new Error('TODO: ...')` と書いてあるだけ）で、押しても
「まだ実装されていない機能があります」というエラーが出る状態です。この4つを埋めるのが
今回のワークショップのゴールです。

---

## 追加してほしい機能一覧（実際のissueに近い書き方）

sub-issueを作るときに「関数を実装する」という技術目線だけでなく、
「アプリのユーザーとしてどんな機能がほしいか」という目線でも書けるように、
機能要望として一覧にしておきます。sub-issue本文の「やること」を書く際の
言い回しの参考にしてください。

- おみくじを引いたら、大吉〜凶のような運勢が表示されてほしい
- 運勢と一緒に、その日のラッキーカラーが表示されてほしい
- 運勢と一緒に、その日のラッキーアイテムが表示されてほしい
- 運勢の内容に合わせて、応援してくれるメッセージが表示されてほしい（凶のときは励ましてくれる、大吉のときは一緒に喜んでくれる、など）

※ 各機能の技術的な仕様（関数名・入出力の形）は、このあとの「参考仕様 A〜D」を参照してください。

## 参考仕様 A: 運勢を判定する関数 (`getFortune`)

**ラベル案**: `good first issue`
**ブランチ名の例**: `feature/issue-2-fortune`

**本文**:
```
## やること
`app-logic.js` の `getFortune(index)` 関数を実装してください。

## 仕様
`index` (0〜4の整数) を受け取り、対応する運勢のラベル(文字列)を返します。
ラベルの中身（「大吉」のような文言）は自分で自由に考えてください。

ただし、次の2つを満たす必要があります。
- index 0〜4 に対応する5つのラベルが、すべて異なる文字列であること（重複しない）
- 同じindexを渡したら、いつも同じ文字列を返すこと（実行のたびに変わらない）

## ヒント
- 配列を1つ用意して、`index`番目の要素を返すだけでOKです
- 実装例は `app-logic.js` にある `getLuckyNumber` 関数を見本にしてください（同じ考え方です）

## 受け入れ条件
- [ ] `getFortune` を実装した
- [ ] `node --test tests/*.test.js` を実行し、`getFortune`のテストが通る
- [ ] 他の担当者の関数(未実装のまま)には手を入れていない
```
